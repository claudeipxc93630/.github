<h2>一、环境层：时区、语言、UA 三件事先对齐</h2>

<p>这一层和 IP 无关，却最常出问题。出口在洛杉矶，系统时区还是东八区，浏览器语言是中文，UA 却报了一个欧洲版本，三个信号互相打架。服务端未必逐个校验，但一旦进入人工复核，这些矛盾都会被翻出来。</p>

<p>做法很朴素：给每个账号建独立的浏览器配置目录，把时区、语言、UA 固定在这个目录里。用 Chrome 的话是 <code>--user-data-dir=/data/profiles/a1 --lang=en-US</code>，系统时区用容器或虚拟机隔离，不要在同一个系统里靠改设置来回切。用 Playwright 的话，创建上下文时一次性写死：<code>browser.new_context(locale="en-US", timezone_id="America/Los_Angeles")</code>，比事后改配置可靠。</p>

<h3>WebRTC 和 DNS 这两个漏点</h3>

<p>代理只接管 HTTP 流量时，WebRTC 仍可能直连暴露本地地址，DNS 也可能走本地解析器。前者的处理方式是在浏览器策略里关闭非代理 UDP，后者是让 DNS 走代理解析或指定与出口同区的解析器。两条都要在配置完成后实测，不能只看设置项。</p>

<h2>二、接入层：协议、鉴权、本地端口</h2>

<h3>白名单和账号密码怎么取舍</h3>

<p>接入层决定"能不能连上"。住宅代理常见 HTTP(S) 与 SOCKS5 两种，前者兼容性最好，后者对非 HTTP 流量更友好。鉴权方式分白名单和账号密码，白名单适合固定办公出口，账号密码适合移动办公。参数上要确认四件事：主机、端口、用户名密码、是否支持长连接。</p>

<h2>三、绑定层：让指定账号只走指定地址</h2>

<p>绑定有两种实现：客户端侧按配置文件绑定，服务端侧按账号绑定固定出口。前者灵活，适合本地多开；后者稳定，适合服务器上的自动化任务。两种可以叠加，但不要和"全局系统代理"混用——全局代理会让所有进程都走一条线，最容易出现账号串线。</p>

<h3>用环境变量做进程级绑定</h3>

<p>命令行工具优先用环境变量，作用域清晰：<code>export https_proxy=http://user:pass@host:port http_proxy=http://user:pass@host:port</code>，再在同一条命令里跑任务，退出即失效。这样同一个 shell 里可以按需切换，不会污染其他进程。</p>

<h2>四、校验层：三层对齐才叫配好</h2>

<p>配置完不要急着登录，先做四项校验。第一项看出口：<code>curl -x http://user:pass@host:port -s https://ipinfo.io/json</code>，确认 ip、city、org 三项与你预期一致。第二项看 DNS 解析结果是否落在同一地区。第三项在浏览器里打开 WebRTC 检测页，确认没有本地地址泄露。第四项看时间戳，服务端时间与你本地时间差不要超过几分钟。</p>

<h2>五、出问题按这个顺序退，不要乱换 IP</h2>

<p>第一步退回上一个可用状态：把配置回滚到昨天能正常登录的那份，确认问题是配置改动引起还是环境本身变化。第二步查账号侧：登录记录里最近一次成功登录的地区和时间，与你当前出口是否吻合。第三步才动出口：换一条同地区的备用地址重试。顺序反了，就会陷入"换 IP—还是不行—再换"的循环，把可用的地址也消耗掉。</p>

<h3>回滚要留一份可执行的快照</h3>

<p>每次改动前把配置文件、环境变量、浏览器目录路径记成一个文本快照，放在版本管理里。回滚时照着快照恢复，而不是凭记忆点设置。这一步花两分钟，能省掉后面两小时。</p>

<h2>常见问答</h2>

<h3>配置都对，为什么还是提示环境异常？</h3>

<p>答：先查账号侧而不是网络侧：近期是否有异地登录、是否更换过设备、是否在短时间内多次输错密码。这些行为本身就会触发验证，与出口质量无关。</p>

<h3>HTTP 代理和 SOCKS5 选哪个？</h3>

<p>答：只跑浏览器和 HTTP 接口，HTTP 代理足够且兼容性好；需要跑非 HTTP 协议或希望少改应用配置，选 SOCKS5。两者都能用时优先选服务商主推的那种。</p>

<h3>一个浏览器配置文件能挂两个账号吗？</h3>

<p>答：技术上可以，但会共享 Cookie 和缓存，排查时无法区分。建议一个配置文件对应一个账号，目录名用编号而不是邮箱，避免路径里带个人信息。</p>

<h3>出口固定后还需要定期检查吗？</h3>

<p>答：需要。建议每周跑一次四项校验并记录，观察延迟和归属是否变化。地址被回收或线路调整通常先体现在延迟和丢包上，早发现能早换。</p>
